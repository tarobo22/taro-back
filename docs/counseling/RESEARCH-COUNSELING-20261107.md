# 여운 | RAG·상담 논문 기반 프롬프트 설계
기준: 2026-11-07 · 구현 커밋: 4e80d4bac5198eef2b309f75186283b988a9deee

> 이 문서는 연구·구현 당시의 기록이다. 후속 요청에서 실제 GPT 48회·12사례 A/B 평가를 완료했다. 최신 품질·시간·비용과 실패 원문은 [실측 보고서](ab-20261107/README.md)에 있다. 아래의 미실시 표기는 연구 구현 시점 기준이다.

## 결론
**현재 채택한 패턴은 ESConv의 대화 전략을 참고한 ‘전략별 프롬프트 분리(Strategy pattern)’다.** 기존 개인사전·최근 대화·카드 의미 RAG와 결합했다. 탐색·경청·조언별 지침을 서버가 선택하고, 경청 모드의 불필요한 질문·행동·카드·정보 출력과 여러 행동 제안은 코드 계약으로 거절한다.

이는 텍스트 프롬프트·문맥 설계이며 모델 가중치 학습이나 soft prompt tuning을 수행한 것은 아니다. 실제 GPT A/B 품질·지연 평가는 아직 실행하지 않았다. 논문 성과를 여운의 개선 수치로 옮겨 적지 않는다.

## 1. 원문에서 검토한 근거
| 연구 | 원문·검토 범위 | 핵심과 이번 적용 판단 |
|---|---|---|
| Lewis et al., RAG, NeurIPS 2020 | [원문](https://arxiv.org/pdf/2005.11401), §2·Figure 1 | 검색한 지식을 생성에 연결한다. 여운에서는 본인 용어·대화·카드 의미를 참고한다. 원 논문의 DPR·BART 공동 학습을 재현한 것은 아니다. |
| Liu et al., ESConv, ACL-IJCNLP 2021 | [원문](https://aclanthology.org/2021.acl-long.269.pdf), §3.2·Figure 3·§5.2·Appendix B/C | 탐색·위로·행동과 지지 전략을 대화에 맞게 조절한다. 여운의 세 프롬프트 전략을 설계하는 핵심 근거로 선택했다. 학습된 전략 토큰은 사용하지 않았다. |
| Rashkin et al., EmpatheticDialogues, ACL 2019 | [원문](https://aclanthology.org/P19-1534.pdf), §1~3 | 주제만 맞는 말과 감정을 알아주는 말을 구분한다. 구체적인 감정·상황 반영을 평가 기준에 넣는다. |
| Basar et al., MI 반영 응답 평가, HuCLLM 2024 워크숍 | [원문](https://aclanthology.org/2024.hucllm-1.4.pdf), §3~4.2 | 반영 응답의 적절성·구체성·자연스러움·참여성을 사람에게 평가했다. 평가 항목을 참고하며, 모든 상담에서 질문을 금지하는 규칙으로 일반화하지 않는다. |
| Lester et al., Prompt Tuning, EMNLP 2021 | [원문](https://aclanthology.org/2021.emnlp-main.243.pdf), §1~2 | 학습 가능한 soft prompt를 최적화하는 방식이다. 이번 텍스트 지침 변경과 명확히 구분한다. |
| Rafailov et al., DPO, NeurIPS 2023 | [원문](https://arxiv.org/pdf/2305.18290), 초록·§3~4 | 선호·비선호 쌍으로 응답 선호를 학습하는 방법이다. 검수 데이터와 학습 환경이 확보된 뒤의 후보이며 이번에는 실행하지 않았다. |

위의 적용 판단은 논문을 이 서비스에 맞춰 해석한 설계 결정이다. 영어 대화·별도 모델·QA 벤치마크의 결과가 한국어 타로 상담 품질이나 치료 효과를 보장하지 않는다. 타로는 마음을 돌아보는 상징으로 사용하며 내담자의 진단·상대 속마음·미래를 확정하는 근거로 사용하지 않는다.

## 2. 어떤 튜닝 방법을 쓸 것인가?
| 방법 | 해결하려는 문제 | 이번 선택 |
|---|---|---|
| 전략 조건부 프롬프팅 | 상황을 듣기 전에 조언, 경청 요청 무시, 과한 질문·행동 | **지금 적용.** 단계별 지침·직접 작성한 말투 예시·구조 계약을 분리 |
| RAG / 문맥 설계 | 개인 별명 오해, 카드와 관계없는 말, 사연 누락 | **기존 구현과 결합.** 본인 자료만 조회하고 카드 ID·참고 ID 검증 유지 |
| SFT | 검수 사례가 축적됐을 때 반복되는 한국어 말투·전략 오류 | 후속 후보. 좋은 예시를 학습하며 개인정보·최신 사실 암기를 목표로 하지 않음 |
| DPO | 두 답변 중 더 공감적이고 덜 단정적인 응답 선호 | 후속 후보. 같은 입력의 선호 쌍과 평가자 일치도 필요 |
| Soft prompt / LoRA | 직접 운용할 모델의 파라미터 효율 학습 | 이번 GPT API 구현에는 미적용. 별도 모델·학습 환경 선택이 먼저 |

OpenAI 공식 문서의 현재 제공 일정에 따르면 2026-05-07부터 이전에 파인튜닝을 하지 않은 조직은 학습 작업을 만들 수 없으며, 기존 고객에도 추가 제한과 종료 일정이 있다. 이 프로젝트의 학습 사용 이력을 확인하지 않았으므로 “API 결제만 하면 SFT·DPO를 즉시 실행한다”는 계획을 세우지 않는다. [제공 일정](https://developers.openai.com/api/docs/deprecations#update-to-openais-self-serve-fine-tuning), [SFT 문서](https://developers.openai.com/api/docs/guides/supervised-fine-tuning), [DPO 문서](https://developers.openai.com/api/docs/guides/direct-preference-optimization).

권장 순서는 **프롬프트+RAG 기준선 평가 → 반복 오류 분류 → 검수 데이터 확보 → 지원되는 학습 환경에서 SFT → 필요하면 DPO**다. 현재 권장한 첫 단계의 코드만 적용했다.

## 3. 적용한 대화 정책
| 서버가 고르는 전략 | 프롬프트가 요구하는 말 | 코드에서 강제하는 범위 |
|---|---|---|
| exploration | 감정을 먼저 반영하고 확인된 고민만 요약. 모호하면 질문 하나, 이미 답한 내용은 다시 묻지 않음 | 기존 Analysis 스키마·개인 의미 인용·사용자 확인 계약 유지 |
| comforting / listen | 사연의 부담·노력을 반영. 억지 긍정·상대 비난·허구의 자기 경험 없음 | actions=[], tarot=[], facts=[], follow_up_question=null |
| action / advice | 확인한 고민과 카드에 연결해 선택 가능한 작은 행동 하나 | actions가 정확히 1개, 기존 카드 ID·출처 ID·소유권 검사 유지 |

정정이 들어오면 다시 탐색할 수 있다. 세 단계를 정해진 횟수의 질문으로 강제하지 않는다. 경청 출력 검증은 사용자 확인 후 compose 응답에 적용하며, 진입·사용자 확인 동선은 기존 계약을 유지한다. ESConv의 자기 경험 공유 전략은 실제 경험이 없는 AI가 꾸며 말하지 않도록 채택하지 않았다. 숨겨진 사고 과정을 수집·저장하거나 사용자에게 길게 출력하는 기법도 추가하지 않았다.

~~~python
mode = payload.get("response_mode", "advice")
strategy = reply_strategy(mode)
result = self._structured(strategy.render(COMPOSE),
                          payload, CounselResult)
return validate_reply_strategy(result, mode)
~~~

## 4. RAG와 이상한 말의 관계
| 오류 | 줄이기 위한 설계 | 아직 남는 한계 |
|---|---|---|
| 개인 별명의 뜻을 지어냄 | 본인 사전의 관련 용어 최대 8개, 모르면 질문 | 키워드 검색이므로 의미 유사도·별칭 일반화는 약함 |
| 고민을 못 듣고 일반 조언 | 최근 최대 10개 메시지·6,000자, 전략별 지침 | 사연을 실제로 잘 이해했는지는 사람 평가 필요 |
| 상담을 정보 검색으로 바꿈 | 일반 고민은 검색 없음, 필요한 공개 개념만 최대 1회 | 모델의 의도·검색 필요 판단이 항상 맞는다는 보장은 없음 |
| 카드에 없는 해석·근거 생성 | Python 무작위 추첨 결과·카드 의미만 전달, ID 일치 검사 | 문장의 의미적 타당성을 ID 검사만으로 증명할 수 없음 |
| 경청 모드에서 행동·질문 강요 | 출력 계약 위반은 게시하지 않고 오류 처리 | 문장 안의 은근한 지시·부자연스러운 말투는 별도 평가 |
| 다른 사람 정보가 섞임 | 기존 owner 격리·RLS·동의·삭제 재확인 | 이번 작업은 외부 침투 테스트를 수행한 것이 아님 |

개인사전·마음기록을 공용 학습 데이터로 옮기지 않았다. 프롬프트 지침은 서버의 고정 텍스트이며 사용자·사전·웹 문장은 user 입력의 인용 데이터로 남는다.

## 5. 재현 가능한 검증과 평가 계획
### 실행한 검증
- 새 계약 테스트 9개의 의도된 RED를 확인하고 구현했다.
- 새 전략·기존 어댑터·기존 RAG 단위 검사 **28 passed**.
- 구현 커밋 4e80d4b의 [원격 전체 CI 588 passed](https://github.com/tarobo22/taro-back/actions/runs/42269331242).
- 실제 GPT 호출·SFT·DPO 학습·부하 테스트는 이번에 실행하지 않았다.
- 이 검사는 전략 선택·데이터 경계·출력 형식·추가 자동 호출 차단을 검증한다. 공감 점수나 환각 감소율을 측정한 것은 아니다.

### 실제 모델 비교는 이렇게 한다
1. 기준선 f93bb9e와 개선판 4e80d4b를 같은 모델·동일 입력·같은 자료·동시성 1로 비교한다.
2. 첫 공감 답변과 확인 후 조언을 분리해 기록한다. 전체 지연·출력 토큰·검색 호출 수를 함께 남긴다.
3. 적절성·구체성·자연스러움·대화 지속성을 평가한다. 추가로 사연 왜곡·성급한 조언·무근거 단정·정정 반영·선택권 존중을 체크한다.
4. 출력 순서를 가리고 둘 이상이 독립 평가한 뒤 불일치를 검토한다. 짧은 문장이나 높은 친절 점수만으로 안전·정확도를 대신하지 않는다.
5. 개발 예시와 겹치지 않는 별도 평가 문항을 고정한다. 기존 50개에는 프롬프트 개발 예시와 겹치는 사례가 있어 블라인드 성능 검증으로 간주하지 않는다.
6. 결과를 확인한 뒤에만 “개선했다”는 수치·우열을 포트폴리오에 추가한다.

예를 들어 “합격했는데 친구에게 말하기가 미안해”, “가족을 돌보느라 내 계획을 미룬 게 허무해”, “지금은 말로 답하기보다 잠깐 쉬고 싶어”, “아까 말한 은하는 사람 이름이 아니라 동아리야”처럼 목표·정정·대화 속도가 다른 문항을 분리 평가할 수 있다. 이는 평가 설계 예시이며 실행 결과가 아니다.

### 학습 데이터를 만들 때
- 기존 50개 개발·회귀 사례와 신규 블라인드 평가 대화를 학습용으로 섞지 않는다.
- SFT 예시는 사용자 문장뿐 아니라 직전 맥락·허용된 개인 정의·카드와 원하는 응답을 함께 검수한다.
- DPO에서는 같은 입력·같은 카드의 두 응답을 비교한다. “그 사람은 널 싫어해”처럼 단정하는 답보다 감정을 반영하고 선택권을 남기는 답을 선호하되 무조건 동의하는 말을 정답으로 만들지 않는다.
- 실제 개인 대화는 별도 허락과 비식별 처리 없이 학습·공용 RAG에 재사용하지 않는다. 이번에는 직접 작성한 짧은 예시만 지침에 넣었다.

## 6. 포트폴리오에 넣을 정확한 표현
> NeurIPS 2020 RAG와 ACL 2021 ESConv를 검토하고, 개인사전·대화·카드 문맥에 전략별 프롬프트를 결합했다. Strategy 패턴으로 탐색·경청·조언 지침을 분리하고 경청 모드의 불필요한 질문·행동 출력 등을 계약 테스트로 차단했다. 실제 모델 A/B 품질·지연 평가는 미완료이며 가중치 파인튜닝을 수행한 것으로 표기하지 않았다.

**구현한 것:** 세 전략·출력 계약·기존 RAG 연결·버전 식별 esc-strategy-20261107-v1·새 검증.
**아직 하지 않은 것:** 가중치 학습, 임베딩 검색, 실제 GPT A/B 평가, 상담 효과·환각 감소율·응답 속도 개선의 입증.
