## 2. 사용자가 경험하는 상담
**이야기 입력 → 짧은 공감 → 의미·입장 확인 → 카드 추첨 → 짧은 조언 하나 → 마음기록·이어가기**

- “그것 때문에 너무 화나.” → “화가 많이 나셨겠어요. 괜찮으시면, 어떤 일이 있었는지 조금 들려주실래요?”
- 학생·직장인 등 사용자가 말한 입장에서 이해한 내용을 확인한다. 상대의 의도나 사용자의 잘못을 단정하지 않는다.
- 장학금 조회·메일 처리 같은 일반 정보 업무 대신 그와 관련한 마음과 고민을 묻는다.
- 일상 고민에는 웹 검색하지 않는다. 낯선 상담 개념이 정말 필요할 때만 최대 한 번 참고한다.
- 카드가 화면 위에 남아 있고 아래에서 짧은 조언을 읽는다. 참고 링크는 필요한 경우 펼쳐보도록 배치했다.
- 위 문장과 기존 화면 검수 이미지는 편집·합성 예시다. 실제 GPT 평가 결과로 제시하지 않는다.

## 3. RAG는 어떻게 사용했는가?
**RAG는 본인 사전의 키워드 검색 결과·최근 대화·카드 의미를 참고한다.**

**임베딩·벡터 검색은 구현하지 않았다.**

| 참고 정보 | 선택 방식 | 범위 |
|---|---|---|
| 개인사전 | 사용자 정의 용어를 정규화해 현재 문장에서 검색 | 본인 소유 사전, 관련 항목 최대 8개 |
| 대화 문맥 | 최근 기록을 길이 예산 안에서 선택 | 최대 10개 메시지·6,000자 |
| 타로 의미 | 서버에서 뽑힌 카드 ID의 기본 의미 사용 | 선택한 1장 또는 3장 |
| 외부 참고 | 상담 개념 확인이 필요한 경우에 한정 | 최대 1회 검색, 본인 대화 범위 캐시 10분 |

검색 코드의 핵심은 아래와 같다.
~~~python
def retrieve_definitions(text, entries, limit=8):
    query = normalized(text)
    matches = [v for v in entries
               if normalized(v["term"]) in query]
    return sorted(matches,
                  key=lambda v: len(normalized(v["term"])),
                  reverse=True)[:limit]
~~~
출처: [개인사전 검색 코드](https://github.com/tarobo22/taro-back/blob/codex/counseling-rag-20261107/api/domain/counseling.py#L96), [상담 조합 코드](https://github.com/tarobo22/taro-back/blob/codex/counseling-rag-20261107/api/application/counseling.py#L155).

### 아키텍처와 데이터 보호
**React / RN 화면 → 별도 CounselingApi → FastAPI HTTP 어댑터 → 상담 유스케이스·도메인 → 포트 → PostgreSQL / OpenAI 어댑터**

| 항목 | 반영 내용 | 확인의 한계 |
|---|---|---|
| 사용자 격리 | 서버 세션으로 사용자 결정, owner_id 입력 거부, DB RLS·제한 역할 | 코드·통합 검사 기준이며 외부 보안 감사는 아님 |
| 개인 기억 | 명시한 정의만 저장, 수정·삭제·대화 한정 기억 | 의미 유사도를 통한 장기 기억 검색은 없음 |
| 중복·실패 처리 | 요청 키 중복 방지, 재시도 시 카드·확인한 자료 유지 | 실제 제공자 장애·통신 환경 평가는 남음 |
| 동의·삭제 | 외부 호출 전 동의 재확인, 생성 중 삭제 시 후속 게시 차단 | 운영 환경 검증은 남음 |
| 초안·음성 | 계정별 메모리 초안, 기기 음성·검토한 전사 입력 | 초안은 앱 프로세스 종료 후 복구하지 않음 |

상담은 사용자를 지지하되 타인의 마음, 진단, 미래 결과를 카드로 확정하지 않는다. 확인된 카드 ID·참고 자료만 조합하도록 구조 검증을 넣었다.

## 4. 성능 측정: 부하 테스트 제외
**동시 요청을 보내는 부하 테스트는 이번에 실행하지 않았다. 한 번에 하나씩 내부 함수를 실행해 처리시간만 확인했다.**

조건: 로컬 Python 프로세스, 합성 사전 200개, 최근 대화 10개, 카드 78개 중 3장. 항목마다 준비 실행 5회 후 순차 50회 측정. 시간은 perf_counter_ns로 측정했다.

| 측정 항목 | 중앙값 | p95 | 표본 |
|---|---|---|---|
| 개인사전 200개에서 검색 | 0.0177ms | 0.0196ms | 50회 |
| 최근 대화 10개 정리 | 0.0007ms | 0.0008ms | 50회 |
| Python 카드 3장 추첨 | 0.0081ms | 0.0088ms | 50회 |

이 수치는 직전 성능 측정의 콘솔 기록이다. 함수 실행시간만 포함하며 DB 조회·프롬프트 전송·네트워크·GPT 생성·화면 렌더링은 포함하지 않는다. 실제 상담 전체 지연이나 다른 기기에서의 성능을 이 수치로 판단할 수 없다. 과거 부하 측정 기록은 보존하되 이번 성능 평가 결과에서 제외했다.

### 실제 AI 성능·품질의 현재 상태
| 항목 | 현재 상태 |
|---|---|
| 서버 준비 확인 | HTTP 200, available=false |
| 실제 OpenAI 호출 | 0건 |
| 첫 공감 답변까지의 시간 | 미측정 |
| 확인 후 최종 조언까지의 시간 | 미측정 |
| 상냥함·맥락 이해·RAG 활용 정확도 | 실제 모델 평가 미실시 |
| 50개 평가 예제 | 상담 중심으로 재작성 완료, 실제 모델 50건 평가 완료와 다름 |

기본 설정은 gpt-5-mini, reasoning effort low다. 출력 토큰 상한은 이해 확인 2000 / 최종 조언 2500 / 드문 개념 참고 900이다. 이는 설정 완료이며 실제 속도 개선이 입증됐다는 뜻은 아니다. 서버에서 모델·상한을 바꿀 수 있다.

실제 연결 후에는 동시성 1로 첫 공감·최종 조언의 시간을 나눠 측정한다. 입력에 “화나”, “그냥 들어줘”, “내 뜻은 그게 아니야”를 포함하고, 불필요한 검색 여부와 공감의 자연스러움을 함께 검토한다. 숫자·스키마 검사만으로 상담 품질을 합격 처리하지 않는다.
