# P0 application composition

`api/main.py` is the only production composition root. It registers v1 compatibility routes and v2 identity, bootstrap, catalog, consent, reading, conversation, job, transcription, journal, feedback, and private-data routes. Constructors do not acquire SQL connections. Migrations remain an explicit pre-start command: `python -m api.migrate`.

V1 and v2 use the same owner and bearer. Session material is returned only at creation, hashed at rest, valid for 180 days, and renewed without silently replacing the guest identity. Authentication rejects expired, deleting, and erased identities. The production v1 services also take the shared owner lifecycle lock inside every unit of work; authentication alone cannot prevent an already-admitted writer from racing erasure.

The reading context supplies the AI reading-source port. The journal context validates owned reading/turn references and invalidates queued jobs when a selected record is deleted. Privacy export and erasure execute all three contexts' explicit callbacks inside the same owner-locked transaction. Receipt-only polling can observe the minimal completed erasure status after token revocation, but can never download an export.

The lifespan starts one leased AI worker and one maintenance loop per API process. SQL `SKIP LOCKED` and lease fencing coordinate multiple processes. Maintenance recovers abandoned leases, processes accepted privacy requests, and purges expired audio, export bytes, receipts, daily anchors, and journal retry references. Provider I/O holds no SQL transaction or owner lock. Shutdown lets the bounded provider call finish its guarded completion before closing the pool. Operational failures log exception classes only.

`Settings` owns infrastructure configuration; shared JSON owns product limits. Optional `OPENAI_MODEL` and `OPENAI_TRANSCRIPTION_MODEL` enable their respective server providers. Private audio defaults to ignored `.local/private-audio`; production must supply a private server-user directory. `ALLOW_CANDIDATE_DECKS=true` is a prototype allowance for the recorded candidate deck, not publication approval. Set it false for a release that requires published assets.

`create_app` accepts injected result/transcription providers and an audio-store port. Integration tests use these ports with real PostgreSQL and the real worker. They do not call OpenAI or register credentials. The verified end-to-end API sequence covers session/bootstrap, opaque card slots, explicit journal context, committed AI result, source-linked journal, feedback, private ZIP export, full erasure, receipt polling, and revoked v1/v2 access. A separate sequence proves local guidance works without consent/provider calls and queued cancellation is explicit.

The owner AI limit is deliberately kept at the existing 20 attempts/day, with 200 globally. The earlier planning value of 30 is not an implemented limit increase. Actual provider quality, store signing, production HTTPS/hosting, and asset publication approval remain separate release checks.
